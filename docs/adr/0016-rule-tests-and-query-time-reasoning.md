# ADR 0016: Rule tests and query-time reasoning over the virtual graph

Status: accepted.

## Rule tests

A job may carry `tests` (`given`, `expect`, `absent`, `exact`, Turtle with shared `prefixes`). The `test` operation runs
a job's own reasoner and rules over the data a test supplies and compares the output; with no `job` it runs every job
that has tests. It reads nothing from the store and writes nothing. Tests are not serialized with the job, so editing
one never changes the job's fingerprint or makes it stale. Bad Turtle, blank nodes in expectations and tests that check
nothing are rejected when the configuration loads. `just rule-tests` runs them against a stack; the e2e script checks
that they pass and that running them leaves the store unchanged. A test of a chained job puts the upstream conclusions in
`given`. The live jobs carry nine tests, including one that records that `work-sparql` (single pass) does not derive what
`work-jena` (chained rules) does.

## Reasoning in Ontop

Ontop is given the ACME ontology (`sidecars/federation/ontop/ontology.ttl`, generated by `scripts/seed/acme_postgres.py`,
`ONTOP_ONTOLOGY_FILE`). It then answers `rdfs:range` and similar axioms at query time: the two loss-reserve amounts in
Postgres are `ins:LossReserve` without any job or copy of the data.

Consequence for `acme-live`: its input is `CONSTRUCT { ?s ?p ?o }` against Ontop, which now already contains the types
Ontop entails, and a derived graph holds only what a job adds. The job therefore derives 31 types where the stored copy's
job derives 40; the other 9 come from Ontop. The correct equivalence is between closures: Ontop's types plus the job's
equal the stored copy's asserted plus derived types (81 each, checked in the e2e script and shown by the workspace query
"Where each inferred type comes from when reading live").

Limits: Ontop reasons in the OWL 2 QL fragment only (ranges, domains, subclass and subproperty), so OWL-RL rules beyond
that still need a job. The ACME ontology happens to have no subclass links among the amount classes, so only range-based
typing is demonstrated.
